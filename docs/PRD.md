# Product Requirements Document (PRD) — Sayam Mukherjee Portfolio

## 1. Executive Summary & Purpose
The Sayam Mukherjee Engineering Portfolio (`https://sayammukherjee.in`) is an authoritative digital presence for Sayam Mukherjee, an undergraduate Computer Science Engineering (AI & Machine Learning) student, systems developer, and builder. 

The primary goal of the portfolio is to present verified engineering work, algorithmic capability, project architecture, academic credentials, and systems proficiency to technical recruiters, hiring managers, engineering leads, and open-source collaborators—grounded entirely in authentic data without artificial claims or frontend secret exposure.

---

## 2. Target Audience
1. **Technical Recruiters & Talent Acquisition**: Looking for verified skills in AI/ML (PyTorch, YOLOv8), full-stack web engineering (TypeScript, React, Node.js), algorithmic depth (LeetCode, Codolio), and academic standing.
2. **Engineering Managers & Tech Leads**: Evaluating code cleanliness, architectural discipline, project documentation, GitHub commit activity, and real-world system implementations.
3. **Open-Source Collaborators & Peers**: Reviewing project repositories, technical journal entries, and engineering tools.

## 4. Functional Requirements
1. **GitHub Activity via Snapshot**:
   - Zero client-side GitHub API keys or browser tokens.
   - Frontend consumes cached snapshot (`/data/github.json` or `/github-data.json`) generated by automated background actions.
   - Graceful offline fallback to static verified records if network fails.
2. **Owner Vault / Admin Authentication**:
   - Strictly server-side authentication using HttpOnly session cookies (`vault_session`).
   - Timing-safe validation against `CERTIFICATE_ADMIN_PASSKEY` environment variable.
   - No secrets or passkeys stored in `localStorage` or `sessionStorage`.
   - Rate limiting on authentication endpoints to prevent brute force.
3. **Contact Submission & Validation**:
   - Client and server-side input validation (name, email format, message length).
   - Honeypot anti-bot protection without intrusive CAPTCHAs.
   - Fallback to direct `mailto:` links to guarantee message delivery under any network condition.
4. **Cookie & Consent Management**:
   - Lightweight, non-intrusive consent banner.
   - Granular preferences: Essential Storage (always on) vs. Optional Analytics.
   - Instant persistence in `localStorage` with reactive dispatch.
   - Ability to reopen preferences at any time via the footer.
5. **Dynamic Route Metadata & SEO**:
   - Route-specific `<title>`, `<meta name="description">`, OpenGraph, and Twitter cards.
   - Canonical domain strictly standardized to `https://sayammukherjee.in`.
   - Crawlable `/sitemap.xml` and `/robots.txt` served with correct MIME types.

---

## 5. Non-Functional & Quality Attributes
1. **Zero Secret Exposure**:
   - Zero API keys, GitHub tokens, passkeys, or private credentials in client-side bundles or repository source.
2. **Determinism & Resilience**:
   - Legal pages (`/privacy`, `/terms`) and 404 page render synchronously and deterministically with zero external API dependencies.
3. **Performance & Native Feel**:
   - Sub-1s visual presentation without heavy blocking spinners.
   - Efficient frame rates: no scroll lag, heavy canvas loops, or redundant re-renders.
   - Native scroll performance respecting `prefers-reduced-motion`.
4. **Design & Typographic Restraint**:
   - Premium editorial design language inspired by modern design systems (Apple, Linear).
   - Elimination of "AI slop": no arbitrary glowing gradients, no fake telemetry labels, no nested card clutter.
   - Clean, WCAG AA compliant contrast in both Dark and Light color palettes.
5. **Responsive Fluidity**:
   - Full support from 320px mobile screens to 3840px ultrawide displays.
   - Touch targets meeting or exceeding 44px on mobile devices.

# Architecture & System Design | Sayam Mukherjee Portfolio

## 1. System Architecture Overview
The portfolio is architected as a modern, high-performance web application utilizing a dual-mode deployment structure:
- **Development & Containerized Runtime**: Node.js/Express application (`server.ts`) hosting API endpoints, security middleware, and mounting Vite middleware for instant hot-reloading.
- **Production Server / Static Deployment**: Pure static asset output in `dist/` compatible with Edge/Vercel serverless platforms or self-hosted Node.js containers (`node dist/server.cjs`).

```
[ Visitor Browser ]
       │
       ├─── HTTP/HTTPS Requests ───► [ Nginx / CDN / Edge / Vercel ]
       │                                     │ (Enforces HTTPS & Security Headers)
       │                                     ▼
       ├─── Static Assets (HTML/JS/CSS) ─── [ Dist Folder / CDN Cache ]
       │
       ├─── GitHub Snapshot Fetch ────────► [ /data/github.json ] (Generated by GH Actions)
       │
       ├─── API Calls (/api/*) ───────────► [ Express Server / Serverless Endpoints ]
       │       ├── /api/contact                 ├── In-Memory Rate Limiting
       │       ├── /api/admin/auth              ├── Timing-Safe Passkey Verification
       │       ├── /api/gemini/chat             ├── Server-Side Gemini API Proxy
       │       └── /api/certificates            └── HttpOnly Cookie Validation (vault_session)
```

## 2. Routing Architecture
- **Client-Side Routing**: Implemented via reactive state in `src/App.tsx` synchronized bi-directionally with browser `window.location.pathname` and the History API (`pushState` / `popstate`).
- **Canonical Routes**:
  - `/` (Home)
  - `/about` (About)
  - `/projects` (Projects)
  - `/skills` (Skills)
  - `/ecosystem` (Ecosystem)
  - `/certificates` (Certificates & Credentials)
  - `/journal` (Journal & Technical Notes)
  - `/contact` (Contact)
  - `/privacy` (Privacy Policy)
  - `/terms` (Terms & Conditions)
  - `*` (Custom 404 Catch-All)
- **Direct Navigation & Hard Refresh Guarantee**:
  - Express server handles SPA fallback via `app.get('*', ...)` serving `index.html`.
  - Static hosting (Vercel) routes all non-asset requests to `/index.html` via `vercel.json` rewrites.
  - Critical routes like `/privacy` and `/terms` have zero asynchronous data dependencies, ensuring immediate synchronous hydration without flicker.

## 3. GitHub Snapshot Architecture
To eliminate browser rate-limiting, eliminate personal GitHub token exposure, and maximize performance:
1. **GitHub Actions Workflow** (`.github/workflows/sync-github-data.yml`):
   - Runs on schedule and pushes.
   - Executes `scripts/sync-github-data.mjs` using repo-level `${{ secrets.GITHUB_TOKEN }}`.
   - Fetches repository data, recent commits, and language distributions.
   - Outputs verified snapshot to `public/data/github.json`.
2. **Frontend Ingestion** (`src/services/github.ts` & `src/services/githubSnapshot.ts`):
   - Client fetches static JSON `/data/github.json` with cache headers.
   - Falls back to built-in verified static record if offline or unavailable.
   - **Zero calls** to `api.github.com` originate from the user's browser.

## 4. Security & Authentication Boundaries
1. **Zero Client Secrets**:
   - No `VITE_` prefixed environment variables contain sensitive keys.
   - No API keys or tokens are emitted into the production JavaScript bundle.
2. **Owner / Certificate Vault Authentication**:
   - Authentication is verified on the backend via timing-safe HMAC buffer comparison (`crypto.timingSafeEqual`).
   - On successful passkey verification, the server issues a signed HMAC-SHA256 token stored in an `HttpOnly`, `SameSite=Strict`, `Secure` cookie named `vault_session`.
   - Browser client uses `credentials: "include"` for all privileged API requests.
   - Sensitive passkeys and tokens are never stored in client `localStorage` or `sessionStorage`.
3. **Contact Submission Security**:
   - Server validates name, email format, and message length.
   - In-memory rate limiting (max 5 requests per 15 minutes per IP).
   - Honeypot hidden field (`website`) silently traps automated bots.
   - Request size strictly clamped to prevent payload exhaustion attacks.

## 5. Privacy, Consent & Analytics
- **Consent Service** (`src/services/consent.ts`):
  - State stores: `{ essential: true, analytics: boolean }`.
  - Stored in `localStorage` under `sayam_consent`.
  - Dispatches global `consentchange` DOM event on updates.
- **Analytics Abstraction** (`src/services/analytics.ts`):
  - Centralized wrapper function `trackPageView(path)` and `trackEvent(name, props)`.
  - Checks user consent before transmitting any metric.
  - Only tracks aggregate high-level navigation and conversion interactions; zero PII or keystroke telemetry.

---

## 6. Error Boundaries & Fallback Resilience
- **LegalRouteErrorBoundary**: Wraps `/privacy` and `/terms` so legal documents render even if parent context or third-party libraries encounter an exception.
- **Root ErrorBoundary**: Captures uncaught React exceptions, presenting a recovery interface without crashing the entire DOM.

## 7. Component Architecture & Core Modules

  - `src/components/SiteFooter.tsx`: Streamlined footer with brand identity, contact, legal links.

## 8. Reading Utilities & Progress Indicators
- **Standard Reading Speed**:
  - `src/utils/readingTime.ts`: Calculates estimated reading time using the international benchmark of 200 words per minute (WPM).
  - Normalizes markdown, code blocks, lists, and headings to provide accurate word counts and minute estimates.
- **Scroll-Synchronized Progress**:
  - `src/components/ScrollProgressBar.tsx`: Global viewport-level reading progress bar pinned to the top of the viewport.
  - `src/components/common/ReadingProgressBar.tsx`: Container-aware reading progress bar with smooth CSS transforms (`will-change: transform`), used inside scrollable modal bodies and long-form article containers.

## 9. Build & Deployment Pipeline
- **Build Pipeline**:
  1. `scripts/generate_build_manifest.js` records build metadata.
  2. Vite compiles client React code, CSS modules, and Tailwind v4 directives into `dist/`.
  3. `esbuild` bundles `server.ts` into a standalone Node runtime at `dist/server.cjs`.
- **Runtime Targets**:
  - Edge/Static: Host `dist/` directly on Vercel/Netlify with rewrites configured in `vercel.json`.
  - Full-Stack Node: Run `node dist/server.cjs` for containerized environments requiring Express API proxying.
